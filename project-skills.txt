# Project-scoped skills to put on the global discovery path.
#
# Why a recorded list and not a directory scan. Claude discovers skills from
# ~/.claude/skills only. A project-scoped skill lives in
# <project>/.claude/skills/<name>, so it is invisible from any other project
# unless something links it. ~/.claude is not a host bind mount in the
# devcontainer, so every link is destroyed on a rebuild.
#
# wire.sh used to be given a directory sweep instead of this file. The dry run
# on 2026-08-18 found why that is wrong: two projects each shipped a skill
# named `orchestrator`, and they were different files -- 278 lines against 370.
# A sweep links whichever it reaches last and says nothing. It also picked up
# seven more metronome-core skills that nobody asked to make global. Discovery
# guesses at intent; a list states it.
#
# Both were renamed on 2026-08-18 for what actually distinguishes them, which
# is the input each one takes, not the project each one sits in:
#
#   plan-orchestrator   takes a written plan file and shards it into work
#                       packages for domain-scoped subagents.
#   skill-orchestrator  takes a request and delegates it across specialist
#                       skills, writing a new skill when one is missing.
#
# skill-orchestrator was listed here until 2026-08-21. outperformer-code held a
# copy differing only in its name: field, so it was promoted to skills/ and
# metronome-core's path became a symlink to it. A promoted skill needs no line
# here: wire.sh links everything under skills/ already.
#
# Format: one `name = path` per line. Blank lines and `#` are ignored. The name
# is what you type as /<name>, and it does not have to match the directory. Two
# lines claiming the same name is an error, not a race.
#
# ${WS} is the workspace: the directory holding the project repos. wire.sh
# substitutes it with the parent of --root, or with --workspace when given. It
# resolves to /workspace in the JS devcontainer and to
# /Users/main/Git-Repos/CodeBases/JS-PSQL-Redis on the macOS host.
#
# Both lines below were written with a literal /workspace prefix until
# 2026-08-21. On the host they resolved to nothing, so wire.sh reported both as
# MISSING and neither skill was ever linked there.
#
# MISSING is the correct result in an environment that does not mount the repo
# in question. The outperformer devcontainer mounts only its own repo, and the
# iOS Mac holds different projects. Nothing is wrong when those two print it.
#
# Adding a project skill is still two steps, and that is deliberate: create it,
# then add a line here. The difference from a hand-made symlink is that this
# file is committed, so a rebuild restores it and a laptop loss does not lose
# the decision.

plan-orchestrator  = ${WS}/mms-repo/mmn-project/.claude/skills/plan-orchestrator

#   design and already reachable from a session whose cwd is that project.
#
#   nextjs-interview-coach sits in metronome-core/.claude/skills/ and is not
#   part of that project. It is untracked there, so git already treats it as
#   something passing through. Where it belongs is the owner's call; until
#   then it is not linked from here.
