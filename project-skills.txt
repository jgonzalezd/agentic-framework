# Project-scoped skills to put on the global discovery path.
#
# Why a recorded list and not a directory scan. Claude discovers skills from
# ~/.claude/skills only. A project-scoped skill lives in
# <project>/.claude/skills/<name>, so it is invisible from any other project
# unless something links it. ~/.claude is not a host bind mount in the
# devcontainer, so every link is destroyed on a rebuild.
#
# wire.sh used to be given a directory sweep instead of this file. The dry run
# on 2026-08-18 found why that is wrong: two projects each shipped a skill
# named `orchestrator`, and they were different files -- 278 lines against 370.
# A sweep links whichever it reaches last and says nothing. It also picked up
# seven more metronome-core skills that nobody asked to make global. Discovery
# guesses at intent; a list states it.
#
# Both were renamed on 2026-08-18 for what actually distinguishes them, which
# is the input each one takes, not the project each one sits in:
#
#   plan-orchestrator   takes a written plan file and shards it into work
#                       packages for domain-scoped subagents.
#   skill-orchestrator  takes a request and delegates it across specialist
#                       skills, writing a new skill when one is missing.
#
# Format: one `name = absolute path` per line. Blank lines and `#` are ignored.
# The name is what you type as /<name>, and it does not have to match the
# directory. Two lines claiming the same name is an error, not a race.
#
# Adding a project skill is still two steps, and that is deliberate: create it,
# then add a line here. The difference from a hand-made symlink is that this
# file is committed, so a rebuild restores it and a laptop loss does not lose
# the decision.

plan-orchestrator  = /workspace/mms-repo/mmn-project/.claude/skills/plan-orchestrator
skill-orchestrator = /workspace/youtube-metronome/metronome-core/.claude/skills/skill-orchestrator
