# Tone Pack Template — schema, shared base copy, and the adding-a-tone checklist

This file is NOT a tone. It defines what every tone pack must contain, and holds the shared base-copy sample all packs rewrite. The skill enumerates `references/tones/*.md` (excluding this file) to discover available tones — adding a pack here is the ONLY step needed to make a tone available.

## Adding a new tone — checklist

1. Copy this file to `tones/<tone-name>.md` (kebab-case name; the filename IS the tone's name).
2. Fill **every** section below. A pack missing any section is invalid and must not be offered or used.
3. Write the Example Rewrites against the **shared base-copy sample** below — never invent a different sample. Same base lines is what makes packs comparable and distinctiveness checkable.
4. Self-check before shipping the pack:
   - Every rewrite passes the 8th-grade readability rule and the global banned-cliché list (`copy-frameworks.md`).
   - Lay your rewrites beside every existing pack's rewrites of the same lines — each of yours must be immediately attributable to your tone. If any line could belong to another pack, sharpen it.
   - Read the rewrites aloud — they must sound like a person, not a persona.

## Shared base-copy sample

A neutral fictional app, one line per copy slot. **Fictional — never let "Trailhead" leak into a real deliverable.**

> **App:** Trailhead — a beginner running app with guided audio plans.
> - **Hero headline:** "Track your runs and build a running habit."
> - **Subhead:** "Trailhead helps beginners go from couch to consistent runner with guided plans."
> - **Feature blurb:** "Guided audio runs tell you when to run and when to walk."
> - **Objection/FAQ answer** (to "I've tried running apps before and quit"): "Trailhead starts easier than you expect and adjusts when you miss a day."
> - **CTA:** "Download Trailhead on the App Store."
